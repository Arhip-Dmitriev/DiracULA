DIRACULA DOCUMENTATION
======================

Overview

Applies to: DiracULA 0.1.x


1. SCOPE
--------

DiracULA, the Dirac Universal Language for Algorithm, is a language for developing quantum
algorithms whose size is not fixed. The number of qudits in a register, their dimension and
the bounds of loops and sums may all be symbols. Every result a program prints, whether a
state, a measurement distribution or the truth of an assertion, is a closed form that holds
for every value of those symbols.

The language is written in Python (numpy and sympy are its only runtime dependencies) and
ships a Lean 4 library against which its results can be certified.


2. ARCHITECTURE
---------------

  Module               Responsibility
  -------------------  ----------------------------------------------------------------------
  diracula.pathsum     Values: symbolic path sums, operators, closed-form summation, Born
                       distributions and mixed states.
  diracula.lang        The parser and interpreter of the language.
  diracula.display     Rendering of values in the unicode, ascii, latex and plot styles.
  diracula.zxsym       The structural translation of one path-sum term to a ZXW diagram.
  diracula.zxview      The ZX view of a state: sums of terms and literal vectors.
  diracula.lean_lang   Lean 4 certificates of results, with its mirror diracula.lean_lsym.
  diracula.lean_sym    The mirror of the Lean normaliser of symbolic sums.
  diracula.zx          The qufinite ZXW diagram model (dimensions, phases, exact scalars,
                       generators, diagrams, bang boxes), its graph listing and its drawing.
  diracula.terminal    Terminal images, the configuration file and PNG rendering.
  diracula.embed       The Python embedding (Program, Value, ula).
  diracula.shell       The diracula command and the interactive shell.
  diracula/lean        The Lean library DiracULA over Mathlib: Base, Sym, SymNorm, SymCanon
                       (symbolic sums and their normaliser), LSym, LDigit, LCanon (integer
                       atoms), Lang (the meaning of programs).


3. VALUES ARE PATH SUMS
-----------------------

A state is a sum of terms, each an amplitude times a sum over bound indices of a product of
kets. Applying a gate is substitution into that form; sums over symbolic ranges are closed
where an identity applies (geometric series, character sums, deltas); measurement is the Born
distribution derived from the closed form, with the post-measurement state, mixed where it
has to be. The same program text therefore yields the same closed form for every value of its
size symbols.


4. THE ZX VIEW
--------------

Any state can be shown as a qufinite ZXW diagram (ZX_VIEW.txt). The diagram is built from
the path sum by diracula.zxsym and diracula.zxview and drawn by diracula.zx.draw. It is a view
only: no result is computed through it.


5. DESIGN PRINCIPLES
--------------------

5.1 Sizes are symbols

A register of n qudits of dimension d is one term, not n kets, for symbolic n and d. A
concrete value is substituted into the closed form at the end at no cost in its size.

5.2 Amplitudes are exact

Every amplitude is an exact expression over rationals, roots of unity and the size symbols.
No global factor is ever dropped.

5.3 Results are derived, not sampled

No state is expanded into an amplitude vector to produce a result, and measurement
distributions are derived, not sampled. rand is the only source of randomness, and it is
explicit in the program.

5.4 Sound, not complete

An assertion passes only when its condition reduces to true. A condition that does not reduce
to a truth value counts as undecided and fails; it is never assumed.

5.5 Results can be certified

certify writes a Lean 4 file proving that the value the program computes, built from its
syntax, equals the printed closed form for every value of its size symbols (LEAN.txt).


6. CURRENT LIMITS
-----------------

  - An assertion whose condition does not reduce to a truth value fails as undecided.
  - Programs using rand, a branch on a value that is not concrete, normalise, floating-point
    format specs or states assigned from Python cannot be certified; nor can results whose
    proof needs an identity the normaliser does not prove yet.
  - An amplitude outside the ZX scalar and phase grammar, such as cos(t) of a real symbol t,
    has no ZX view.
  - The Python API is not yet stable between releases.

-------------------
